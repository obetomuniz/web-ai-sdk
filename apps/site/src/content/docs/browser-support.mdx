- **Stable:** the vendor enables the API by default.
- **Canary/Dev:** an Edge preview that requires a flag.

The wrappers do not detect browser brands or versions. They check the native API and its reported availability. React hooks return `status: "unavailable"`. Vanilla functions can throw a typed unavailability error.

## Chrome specifics

Chrome's [status table](https://developer.chrome.com/docs/ai/built-in-apis) lists Translator, Language Detector, and Summarizer as stable from Chrome 138. Prompt is stable from Chrome 148. Writer, Rewriter, and Proofreader are in **Developer trial**.

The public origin-trial milestone windows documented on the capability pages are historical:

- Writer and Rewriter shared an origin trial from Chrome 137 through 148.
- Proofreader had an origin trial from Chrome 141 through 145.

These origin trials have ended. The current Developer trial label and localhost flags are separate forms of access.

| Surface | Current Chrome localhost setup |
| --- | --- |
| Writer and Rewriter | Enable `#optimization-guide-on-device-model`, `#prompt-api-for-gemini-nano-multimodal-input`, and `#writer-api-for-gemini-nano`; Rewriter shares Writer's flag. |
| Proofreader | Enable `#proofreader-api`. |
| WebMCP | Enable `#enable-webmcp-testing`; production testing uses the origin trial from Chrome 149. |

Chrome documents Translator and Language Detector for desktop. The foundation-model APIs have additional platform, storage, GPU, and CPU requirements. See the [Prompt hardware requirements](https://developer.chrome.com/docs/ai/prompt-api).

Do not infer product behavior from Chromium engine lineage. Check the capability page for each browser.

### WebMCP discovery compatibility

The [current WebMCP draft](https://webmachinelearning.github.io/webmcp/#dictdef-registeredtool) defines `RegisteredTool.inputSchema` as an object. Chromium [landed this change](https://github.com/chromium/chromium/commit/012624d070518db013e880c36cc778445b673489) on September 10, 2026. Chromium Dash records [155.0.8051.0 as the first build](https://chromiumdash.appspot.com/commit/012624d070518db013e880c36cc778445b673489).

| Chrome trial generation | Discovery schema compatibility |
| --- | --- |
| Earlier supported trial builds, starting from the Chrome 149 origin trial | Legacy serialized strings may be returned. |
| Chrome 155, starting at 155.0.8051.0 | Objects are the normative discovery shape. |

The SDK types the optional discovery field as `object | string`. It preserves native values, including omission and malformed legacy strings. It does not parse, stringify, normalize, clone, or detect browser versions.

Use a `typeof schema === "string"` guard when consuming mixed trial generations. The [WebMCP guide](/docs/guides/webmcp/#discovery-schemas) shows the guard. React exposes the same metadata through `tools` and `refresh()`.

String compatibility is temporary. Remove it when supported trial generations no longer require it. Registration continues to accept schema objects. Execution compatibility is described below.

### WebMCP execution compatibility

The [current draft](https://webmachinelearning.github.io/webmcp/#dom-modelcontext-executetool) accepts an optional object input, including arrays. Chromium [changed the native contract](https://github.com/chromium/chromium/commit/23cad65d6e6613d62542b27651c28925acfaffb2) from a required string to optional object input.

Chromium Dash records [155.0.8052.0 as the first build](https://chromiumdash.appspot.com/commit/23cad65d6e6613d62542b27651c28925acfaffb2). [Chrome's imperative API docs](https://developer.chrome.com/docs/ai/webmcp/imperative-api) deprecate string arguments from Chrome 155.

| Chrome trial generation | Native execution input | Native `executeTool.length` |
| --- | --- | --- |
| Earlier supported trial hosts with execution, before 155.0.8052.0 | Serialized JSON string | `2` |
| Chrome 155, starting at 155.0.8052.0 | Original object or array | `1` |

The SDK reads this arity before invoking the native method. It serializes once for legacy hosts and delegates serialization to object-input hosts. It never retries execution or uses browser-version detection. Unrecognized arities reject with `WebMCPUnavailableError` before invocation.

Both arities were verified in installed Chrome 153.0.8010.37 and Canary 155.0.8053.0 binaries with WebMCP enabled. These checks establish compatibility for those builds, not every browser product. Retain legacy support until supported trial hosts no longer require it.

**Migration:** `executeTool(tool, input?, options?)` now accepts `input?: object`. Pass objects or arrays directly; remove caller-side `JSON.stringify()`. Replace primitives with objects that match the tool schema. Omitted or `undefined` input defaults to `{}`; `null` and primitives reject.

Serialization failures reject, including circular data, BigInt values, failing `toJSON()` methods, and objects that serialize to `undefined`. Native results, navigation `null`, and cancellation remain unchanged.

### WebMCP annotation compatibility

The [current draft](https://webmachinelearning.github.io/webmcp/#dom-toolannotations-debugging) defines `ToolAnnotations.debugging` with a default of `false`. Chromium [implemented the member](https://github.com/chromium/chromium/commit/4ba301ad8c7c1e2190707d80aec6bc8aa63a2671). Chromium Dash records [156.0.8067.0 as the first build](https://chromiumdash.appspot.com/commit/4ba301ad8c7c1e2190707d80aec6bc8aa63a2671).

Chrome for Testing 156.0.8072.0 with `#enable-webmcp-testing` returned explicit `true` and `false` values through discovery. It returned `false` when registration omitted the field. Installed Chrome 153.0.8010.53 accepted the field and omitted it from discovery.

The SDK forwards the field unchanged and preserves discovered metadata. It does not add defaults or detect browser versions. Treat an omitted value as `false`.

## Agent consumers

The table above tracks browser API providers only. An agent consumer is a separate product integration. It does not establish `document.modelContext` support in Chrome or another browser.

| Product | Adoption signal | Product surface | Scope and lifecycle | Primary source |
| --- | --- | --- | --- | --- |
| ChatGPT Desktop Site tools | Implemented WebMCP consumer | ChatGPT desktop app built-in browser only | Availability depends on account, selected model, current page, and user permission. Tools do not carry after navigation. Closing the page makes them unavailable. | [OpenAI Site tools](https://help.openai.com/en/articles/20001423-using-site-tools-in-the-chatgpt-desktop-app) |

Users can disable Site tools in the desktop app. The documented consumer behavior does not follow from engine lineage.

The SDK detects the native API on the current document. `document.modelContext` detection cannot prove that an external agent product will discover or invoke a tool.

## Edge specifics

Microsoft enables Summarizer by default from Edge 138. Prompt, Writer, and Rewriter are Canary/Dev previews from 138.0.3309.2. Proofreader is a preview from Edge 142.

Translator and Language Detector shipped in Edge 148. Microsoft Learn Edge 153 and Edge 154 release notes list origin trials for WebMCP and Prompt API sampling parameters.

### Models and hardware are capability-specific

| Edge capability | Documented model path | Documented device-performance condition |
| --- | --- | --- |
| Prompt | Phi-4-mini by default; optional prerelease Aion-1.0-Instruct in Canary/Dev 150.0.4070+ when "Enable prerelease on-device language model" is enabled | High or greater for Phi; Medium/Low only through the prerelease Aion path |
| Summarizer, Writer, Rewriter | Phi-4-mini by default; the [Writing Assistance docs](https://learn.microsoft.com/en-us/microsoft-edge/web-platform/writing-assistance-apis) now document the same optional prerelease Aion override in Canary/Dev 150.0.4070+ | High or greater for Phi; Medium/Low only through the documented prerelease Aion path |
| Proofreader | Phi-4-mini | High or greater; Microsoft does not document an Aion override on the Proofreader page |
| Translator | Task-specific translation models | No Phi/Aion performance-class rule is documented on the Translator page |
| Language Detector | Task-specific language-detection model | No Phi/Aion performance-class rule is documented on the Language Detector page |

Microsoft does not document the Aion path for Proofreader, Translator, or Language Detector.

Current Edge preview flag labels are:

- "Prompt API for on-device language model"
- "Writer API for on-device language model"
- "Rewriter API for on-device language model"
- "Proofreader API for Phi mini"
- "Enable prerelease on-device language model" for the optional Aion override documented for Prompt and Writing Assistance

Summarizer is enabled by default. Translator and Language Detector do not use these generative-model flags.
